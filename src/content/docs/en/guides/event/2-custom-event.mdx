[Previous page](/guides/map/3-event) explained that common basic events are provided as template events, so they can be created with one touch.  
However, once you start creating game mechanisms and presentations, you will quickly notice that they are not enough.  
**What if you want to make them move exactly the way you want? Make a custom event!**

### <M code="f10d"/> How to create a custom event

There are two ways to create a custom event.
1. On the canvas, choose "<M code="e01e"/> Place event" => "<M code="e01e"/> Custom event" from the context menu
2. Select a placed template event and choose "Convert to custom event" from the context menu

In this page, we will create a custom event using method 1.

### <M code="f10d"/> Editing the command list

Try adding a command from the right-click context menu on the command list by choosing "<M code="e150"/> Insert command (Space key)." A long list of commands will appear.

<SS src='docs/custom-event-2.png' alt='' minscale={0.8}/>

If you are familiar with RPG development, you can probably guess what each command does. We cannot introduce every command, so here we will briefly present representative ones.

|Type|Command|Description|
|---------|----------|---------|
|General processing|<M code="eb26"/> Branch|Specifies a condition and runs the following processing if it is met.|
|Variable processing|<M code="ea5f"/> Set variable|Performs calculations and stores the result in a variable.|
|Player / party|<M code="f109"/> Gain / lose item|Gains or loses items.|
|Screen display / input|<M code="e0b7"/> Message|Displays a dialogue window and shows a conversation.|
|Scene control|<M code="e539"/> Move map|Moves the map or current position. A command with the same effect as a portal.|
|Operation / presentation|<M code="eae9"/> Animation|Plays an animation on an event or player.|
|Battle processing|<M code="f06e"/> End battle|Forcibly ends the battle by specifying victory, defeat, or cancellation.|

The added commands can be edited by double-clicking them or choosing "<M code="e745"/> Edit command" from the right-click context menu.

### <M code="e8af"/> What are multiple pages used for?
An event can have multiple pages, and you can switch pages depending on the situation to change its appearance and behavior.
The pages are lined up as <M code="f124"/><M code="f125"/><M code="f126"/>..., and you can set conditions for each page. Then the page with the highest number that matches the conditions is selected.
##### How can this page system be used?
Let's use a treasure chest as an example to explain page usage.
A treasure chest has two states: "contains an item" and "empty after the item is taken." These become two pages.

|Page|Page content|Page selection condition|Trigger condition|Executed event commands|
|---------|----------|---------|------|------|
|<M code="f124"/>|Item not yet obtained|None|Inspect (near)|Gain item, set variable A = ON|
|<M code="f125"/>|Item already obtained|When variable A = ON|None|None|

The variable used for the page change condition is **variable A**. (*See the explanation about variables below.*)
- When variable A = OFF (initial state), page 1 is selected. On page 1, the command list is executed when the nearby inspect button is used. (*See here for the command list.*)
  This command list adds the item and sets variable A = ON.
- Once variable A = ON, the selection condition for the higher-priority page 2 is satisfied, and the event changes to page 2.
- On page 2 there are no commands to execute, so no more items can be taken from this treasure chest.


### <M code="f10d"/> What are variables?


The variables available in RPG-Cobo event commands are as follows.

|Variable type|Variable name|Overview|
|------------------|------------|-------|
|Work variables|W X Y Z|Temporary variables used during event processing (not saved)|
|Event variables|A B C D|Variables saved per event|
|Global variables|G000 ~ G999|Variables that can be read and written by all events|
|System variables|MONEY PTIME MAPID…|Variables that can obtain the state of the game system, such as money, play time, and the current map ID|
|Button state|BTN_UP BTN_LEFT BTN_A…|Variables used to check whether buttons are being pressed|

The "variable A" mentioned in the [multiple page usage section](#multiple-pages-use) above was the event variable A. Since this is saved per event,
if you change the A value of a treasure chest event, that state will be saved permanently, and even if you resume from save data, the chest will remain empty.


If you want to assign a value to a variable, use the "<M code="ea5f"/> Set variable" command.
